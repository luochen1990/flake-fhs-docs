The `modules/` directory is used to organize reusable NixOS modules. The system automatically discovers modules based on directory structure, without manually maintaining `module-list.nix`.

There are only two core concepts:

- **Module**: A single entry convention — a directory with `default.nix` is a directory module; a standalone `.nix` file (not inside any directory module's subtree) is a single-file module
- **Guarded config file** (`.cfg.nix`): A file-level attribute. Its content is wrapped with `mkIf (enable-chain)` and auto-imported by the enclosing directory module

## Module Kinds

### Directory Module

**Identifier**: Directory contains `default.nix`

**Features**:
- `default.nix` is the module entry; can define options and config
- **Unconditionally injects** `<modPath>.enable` option (if not manually defined) — this is required for enable-chain consistency
- Config in `default.nix` is **always applied** (not wrapped with `mkIf`)
- Supports nesting; child modules' enable-chain includes all ancestor modules' enables

**Example**:
```
modules/tweaks/
├── default.nix  # options.tweaks.* + base config (always applied)
└── utils.nix    # helper file, explicitly imported by default.nix
```

### Single File Module

**Identifier**: A standalone `.nix` file that is **not inside any directory module's subtree**

**Features**:
- Directly exported, no enable injection, no enable-chain
- `.nix` files inside a directory module's subtree (except `.cfg.nix`) are **NOT** recognized as single-file modules; they are managed by the enclosing module's `default.nix`

**Example**:
```
modules/
├── utils.nix          # ✅ Single-file module (not inside any directory module subtree)
├── network/           # Directory module
│   ├── default.nix
│   └── helpers/
│       └── util.nix   # ❌ NOT a single-file module (inside network's subtree; default.nix must import it)
└── misc/
    └── helper.nix     # ✅ Single-file module (misc is not inside any directory module subtree)
```

## Guarded Config Files (.cfg.nix)

**Identifier**: Filename matches the configured suffix (default `.cfg.nix`, customizable via `layout.nixosModules.guardedSuffix`)

**Location constraint**: Must reside within a directory module's subtree

**Behavior**:
- Content is wrapped with `mkIf (enable-chain)` (no need to manually write `mkIf`)
- Auto-imported by the enclosing directory module

### Why .cfg.nix?

NixOS modules encourage splitting complex configurations into multiple files for maintainability. But with the traditional approach, every split file requires repeating `lib.mkIf cfg.enable { ... }` to be controlled by a switch — this is pure boilerplate.

The `.cfg.nix` mechanism makes splitting zero-cost: just put the switch-controlled config into a `.cfg.nix` file, and the framework auto-wraps `mkIf` and auto-imports, with no repetitive work.

Comparison:

```nix
// ❌ Traditional approach: every split file must manually write mkIf
# modules/web-server/service.nix
{ config, lib, ... }:
let cfg = config.services.web-server;
in {
  config = lib.mkIf cfg.enable {
    systemd.services.web-server = { /* ... */ };
  };
}

# modules/web-server/firewall.nix
{ config, lib, ... }:
let cfg = config.services.web-server;
in {
  config = lib.mkIf cfg.enable {
    networking.firewall.allowedTCPPorts = [ cfg.port ];
  };
}
```

```nix
// ✅ .cfg.nix approach: framework auto-wraps mkIf and auto-imports
# modules/web-server/service.cfg.nix
{ config, ... }: {
  systemd.services.web-server = { /* ... */ };  // no need to write mkIf
}

# modules/web-server/firewall.cfg.nix
{ config, ... }: {
  networking.firewall.allowedTCPPorts = [ config.services.web-server.port ];
}
```

### enable-chain (precise definition)

A `.cfg.nix`'s `mkIf` condition = the AND of **all ancestor modules' enables** (directories with `default.nix` on the path) AND **the enclosing module's own enable**.

Intermediate directories without `default.nix` (pure path organization) do NOT participate in the enable-chain, but still contribute modPath segments.

### Custom Suffix

The default suffix is `.cfg.nix`, customizable via `layout.nixosModules.guardedSuffix`:

```nix
{
  outputs = inputs@{ flake-fhs, ... }:
    flake-fhs.lib.mkFlake { inherit inputs; } {
      layout.nixosModules.guardedSuffix = ".guarded.nix";
    };
}
```

## Usage

### Use Modules

In `hosts/my-machine/configuration.nix`:

```nix
{
  # All modules are auto-imported via nixosModules.default
  # Directory modules' enable options can be toggled as needed
  services.web-server.enable = true;
  services.web-server.port = 9000;
}
```

### Define a Directory Module (with guarded config)

Take `modules/services/web-server` as an example:

**1. `default.nix`: Define options and base config**

<Aside type="tip" title="Auto Enable">
All directory modules auto-inject `<modPath>.enable` (if not manually defined). You can also define it manually to customize the description.
</Aside>

<Aside type="tip" title="Option Namespace">
By default, option namespaces are not enforced. If you want the framework to automatically validate that option paths match the directory structure, see Strict Options Validation in [Advanced Configuration](../advanced-config/#strict-options-validation).
</Aside>

```nix
# modules/services/web-server/default.nix
{ lib, ... }:
{
  options.services.web-server = {
    port = lib.mkOption {
      type = lib.types.port;
      default = 8080;
    };
  };
}
```

**2. `*.cfg.nix`: Define switch-controlled config**

```nix
# modules/services/web-server/service.cfg.nix
{ config, pkgs, ... }:
{
  // No need to write config = lib.mkIf cfg.enable { ... }
  // The framework auto-wraps this

  systemd.services.web-server = {
    description = "Simple Python Web Server";
    wantedBy = [ "multi-user.target" ];
    serviceConfig = {
      ExecStart = "${pkgs.python3}/bin/python -m http.server ${toString config.services.web-server.port}";
      Restart = "always";
    };
  };
}
```

**3. Split more `.cfg.nix` files as needed**

```nix
# modules/services/web-server/firewall.cfg.nix
{ config, lib, ... }:
{
  networking.firewall.allowedTCPPorts = lib.mkIf config.services.web-server.openFirewall
    [ config.services.web-server.port ];
}
```

### Define a Single File Module

The simplest module form, just write configuration directly:

```nix
# modules/personal-config.nix
{ config, lib, ... }:
{
  // Direct configuration, no enable mechanism
  users.users.alice = {
    isNormalUser = true;
    extraGroups = [ "wheel" ];
  };
}
```

## Output Structure

### Individual Module Outputs

Each module generates a `nixosModules.<path>` output:

| Directory | Output |
| :--- | :--- |
| `modules/web-server/` | `nixosModules.services/web-server` |
| `modules/utils.nix` | `nixosModules.utils` |

### Default Module

`nixosModules.default` includes **ALL** modules:

- All directory modules (with enable injection and `.cfg.nix` mkIf guards)
- All single-file modules (directly active)

```nix
{
  // Import all modules at once
  imports = [ flake.nixosModules.default ];

  // Enable directory modules as needed
  services.web-server.enable = true;
}
```

## Design Decisions

<Aside type="note" title="Why are all directory modules injected with enable?">
Because enable-chain consistency requires every module on the chain to have an enable. If only "modules with .cfg.nix" got enable injected, then when an ancestor module without .cfg.nix appears on the chain, descendant .cfg.nix mkIf conditions would reference a non-existent option and error. Unconditional injection is the simplest and most consistent design.
</Aside>

<Aside type="note" title="What Does nixosModules.default Include?">
All modules (directory modules + single-file modules), following the **Zero-boilerplate** principle. Users only need `imports = [ flake.nixosModules.default ]` to import everything, then enable directory modules as needed.
</Aside>
